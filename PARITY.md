# Parity with pgmem-go

Every test in the pgmem-go suite has a Rust counterpart. `parity/go_tests.tsv` maps each Go test
(package, file, name) to the Rust test that ports it and records its status;
`scripts/parity.py check` (CI job `parity`) verifies every listed Rust test exists.
This file is generated by `scripts/parity_doc.py`.

**Status: 364/564 Go tests ported** (350 with identical assertions, 14 deviations).

How the port is verified: the 315 integration-level tests ported so far (from pgmem-go's `postgres/`, `examples/` and
`exec/` packages) run as Rust integration tests in `crates/pgmem/tests/it/`, driven by a real
Postgres client (tokio-postgres). The same tests also run against real PostgreSQL 18 (CI job
`postgres-fidelity`), and every assertion holds there too. Unit tests of Go-internal packages
(`types`, `storage`, `postgres/parse`) are ported into the corresponding crates.

Pending tests are ported by area in follow-up PRs.

Where a Go test only checked that *an* error occurred, the Rust test usually also asserts the
SQLSTATE and message real Postgres produces.

## Deviations from pgmem-go

pgmem-go approximated Postgres in places (no `numeric`, `date`, `timestamp` or `time` types; raw,
unnormalized jsonb; table-level write-conflict detection; ...). Where its tests encoded such an
approximation, the Rust port asserts what PostgreSQL actually does:

| Go test | What changed |
|---|---|
| `postgres/column_default_test.go` `TestColumnDefault_AlterAddColumnWithDefault` | pgmem-go left existing rows NULL after ADD COLUMN ... DEFAULT; Postgres backfills them, asserted row 1 = 'new' |
| `postgres/current_setting_test.go` `TestCurrentSetting_Known` | server_version asserted to start with "18." (Go: "16.0"); search_path asserted "\"$user\", public" (Go: "public"); timezone accepts "UTC" or "Etc/UTC" (server-config dependent). |
| `postgres/current_setting_test.go` `TestVersion` | "pgmem" substring only asserted when running on pgmem (real Postgres build string lacks it). |
| `postgres/derived_table_test.go` `TestDerivedTable_RequiresAlias` | pgmem-go rejected a derived table without alias; PostgreSQL 16+ accepts it (query succeeds, 4 rows) |
| `postgres/generate_series_test.go` `TestGenerateSeries_Alias` | pgmem-go kept column name generate_series under alias gs; Postgres names the column gs, so gs.generate_series is 42703 (asserted) and gs.gs is used |
| `postgres/generate_series_test.go` `TestGenerateSeries_Joined` | join column gs.generate_series does not exist in Postgres (42703 asserted); join ported as ON gs.gs = t.id |
| `postgres/migration_noops_test.go` `TestMigrationNoop_CommentOn` | COMMENT ON EXTENSION "uuid-ossp" fails (42704) on Postgres unless the extension exists; test creates it first. |
| `postgres/on_conflict_test.go` `TestOnConflict_DoUpdate_ReferencesExisting` | unqualified `name` in DO UPDATE SET expression is ambiguous in Postgres (42702); asserts that error, then the t.name-qualified upsert yields "alice / bob". |
| `postgres/serialization_test.go` `TestSerialization_ConcurrentWritesOneFails` | pgmem-go failed the second COMMIT with 40001 (per-table conflict detection); real Postgres READ COMMITTED commits both inserts of different rows, asserted ids [1 2]. Same-row UPDATE race not tested (blocks on real Postgres). |
| `storage/conflict_test.go` `TestCommit_ConflictDetected_AcrossDelete` | Go aborted an insert that raced a delete of a different row in the same table; Postgres commits both. Deleting the same row twice still conflicts (40001). |
| `storage/conflict_test.go` `TestCommit_Conflict_TwoConcurrentWrites` | Go aborted the second of two transactions inserting different rows into one table (table-level conflict check); Postgres commits both. Conflicts are now row-level (same-row update conflict covered by commit_conflict_same_row_update). |
| `types/bytea_test.go` `TestBytea_RejectsLegacyEscapeFormat` | Go rejected non-hex bytea text input; Postgres accepts the escape format (plain characters stand for themselves) and rejects only malformed escapes. |
| `types/jsonb_test.go` `TestJSONB_BinaryRoundTrip` | Binary jsonb payload is the Postgres-normalized text, not the raw input. |
| `types/jsonb_test.go` `TestJSONB_TextRoundTrip` | Go echoed jsonb input text verbatim; Postgres normalizes jsonb ({"k": "v", "n": 42}). |

Behavioural changes beyond the Go tests' scope (all toward Postgres fidelity):

- No bootstrap `users` table: a new server starts empty, like a fresh Postgres database.
- DDL is transactional (`CREATE TABLE` inside a rolled-back transaction disappears).
- READ COMMITTED sees other transactions' commits at each statement; REPEATABLE READ and
  SERIALIZABLE keep one snapshot. Write conflicts are detected per row, not per table.
- An UPDATE gives the row a new physical position, so unordered scans return updated rows last,
  as Postgres heaps do.
- `now()` is the transaction start time; `server_version` reports 18.0.
- Errors carry Postgres' SQLSTATE, DETAIL and schema/table/column/constraint fields.
